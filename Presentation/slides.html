انگیزه: وقتی REST کافی نیست

در معماری میکروسرویس / ارتباط داخلی سرویس‌ها:

  • JSON برای ترافیک زیاد می‌تواند پرحجم باشد
  • قرارداد گاهی شل است (مستند جدا، توافق شفاهی)
  • استریم واقعی سخت‌تر است (SSE / WebSocket جدا)
REST عالی است برای API عمومی.
برای ارتباط داخلی گاهی ابزار بهتری داریم.

gRPC در یک جمله

کلاینت یک متد را صدا می‌زند؛
زیرش HTTP/2 + Protocol Buffers است.

برای دات‌نتی‌ها:

حسش شبیه Interface مشترک است؛
پیاده‌سازی روی سرور دیگر است، ولی فراخوانی مثل متد لوکال حس می‌شود.

پروتکل بافرز (Protocol Buffers) که به اختصار به آن Protobuf می‌گویند، روش اختصاصی گوگل برای سریالایز کردن داده‌های ساختاریافته است؛ دقیقاً مثل JSON یا XML، اما به صورت باینری، بسیار سبک‌تر، سریع‌تر و کاملاً Strongly-Typed.

Protobuf برای gRPC همان نقشی را بازی می‌کند که JSON برای REST API بازی می‌کند؛ با این تفاوت که خروجی آن متن خوانا نیست، بلکه بایت‌های فوق‌العاده فشرده است.

فایل .proto = قرارداد مشترک

service AccountService {
  rpc GetBalance (GetBalanceRequest)
      returns (GetBalanceResponse);
}
  • منبع حقیقت بین تیم سرور و کلاینت
  • با Build در دات‌نت، کد C# تولید می‌شود
  • سرور: AccountServiceBase
  • کلاینت: AccountServiceClient

فرمول یک متد RPC

rpc نوع ورودی  نام_متد   returns (نوع_خروجی);

و کلمهٔ جادویی:

stream
  • بدون stream → یک پیام
  • با stream → چند پیام پشت‌سرهم

Field Number چیست؟

message GetBalanceResponse {
  string account_number = 1;
  double balance = 2;
  string currency = 3;
}
چیزنقش
اسم فیلدبرای برنامه‌نویس / کد C#
عدد (= 1)شناسهٔ پایدار روی پیام باینری
عدد ایندکس کلاس نیست؛ ID فیلد روی شبکه است.

چرا Field Number مهم است؟

  • JSON اسم می‌فرستد → خوانا ولی پرحجم‌تر
  • Protobuf شماره می‌فرستد → کوچک‌تر و سریع‌تر

قوانین طلایی

  1. شماره را عوض نکن
  2. فیلد جدید = شمارهٔ جدید
  3. کلاینت قدیمی فیلد ناشناس را معمولاً نادیده می‌گیرد

یک پاسخ حجیمچند پیام پشت‌سرهم

معماری در ASP.NET Core

از نظر ASP.NET Core: gRPC یک endpoint دیگر است؛ پروتکل و فرمت پیام فرق دارد.

GrpcChannel و Stub

۱. GrpcChannel

ارتباط پایدار و بادوام به سرور از طریق HTTP/2.

  • مدیریت TCP و Connection Pooling
  • Multiplexing روی HTTP/2
  • امنیت TLS / SSL
  • Timeout، بافر، Gzip، Keep-Alive

۲. Stub (پروکسی کلاینت)

کلاس تولیدشده از .proto که متد را «لوکال» جلوه می‌دهد.

  • سریالایز با Protobuf
  • ارسال روی GrpcChannel
  • دیسریالایز پاسخ به Object سی‌شارپ

راه‌اندازی سرور (خلاصه)

builder.Services.AddGrpc();
app.MapGrpcService<AccountGrpcService>();
public class AccountGrpcService
    : AccountService.AccountServiceBase
{
    // override متدها
}

خطای استاندارد:

throw new RpcException(
    new Status(StatusCode.NotFound, "..."));

کلاینت (خلاصه)

var channel = GrpcChannel.ForAddress("http://localhost:5051");
var client = new AccountService.AccountServiceClient(channel);

var balance = await client.GetBalanceAsync(
    new GetBalanceRequest { AccountNumber = "1001" });

برای Client Streaming بعد از آخرین Write:

await call.RequestStream.CompleteAsync();

Deadline

سقف زمان تماس:

deadline: DateTime.UtcNow.AddSeconds(5)

اگر سرور دیر کند:

StatusCode.DeadlineExceeded

تفاوت با Cancel

  • Deadline: از اول مشخص است («تا ساعت X»)
  • Cancel: وسط کار قطع می‌کنیم

هر دو به CancellationToken سرور می‌رسند.

Interceptor

شبیه Middleware در ASP.NET Core، ولی روی RPC:

کلاینت → Client Interceptor → شبکه → Server Interceptor → متد سرویس

کاربردها

  • لاگ و correlation-id
  • احراز هویت از Metadata
  • متریک مدت‌زمان
  • تبدیل خطا

continuation = همان next() در Middleware.

سوالات تشریحی — ASP.NET Core و کلاینت

بخش دوم · ۱ و ۲ از ۱۰
۱در کانفیگ Kestrel برای سرویس‌های gRPC چه نکته‌ای حیاتی است و پروتکل پیش‌فرض چگونه مدیریت می‌شود؟
سرویس‌های gRPC به بستر HTTP/2 نیاز دارند؛ بنابراین Kestrel باید صراحتاً برای پشتیبانی از HttpProtocols.Http2 تنظیم شود. بدون فعال‌سازی TLS، مذاکرهٔ ALPN انجام نمی‌شود و کلاینت‌ها نمی‌توانند به سرور متصل شوند؛ در نتیجه سرور باید یا از TLS استفاده کند یا در حالت Cleartext (H2C) کانفیگ شود.
۲تفاوت عملکردی دو متد builder.Services.AddGrpc() و app.MapGrpcService<T>() چیست؟
متد AddGrpc سرویس‌های زیرساختی مانند کدک‌های Protobuf، اکتیویتورها، اینترسپتورها و ولیدیشن را در کانتینر DI رجیستر می‌کند. در مقابل، MapGrpcService پیاده‌سازی کلاس سرویس را در Routing پایپ‌لاین دات‌نت نگاشت می‌کند. مسیر نهایی URL بر مبنای نام Package، Service و Method تعریف‌شده در فایل .proto به‌صورت /{package}.{service}/{method} ساخته می‌شود.

سوالات تشریحی — ASP.NET Core و کلاینت

بخش دوم · ۳ و ۴ از ۱۰
۳تفاوت استفاده از gRPC Interceptor با ASP.NET Core Middleware در چیست؟
میدل‌ورهای دات‌نت در سطح پایین‌تر و روی HttpContext عمومی کار می‌کنند و فقط مختص سمت سرور هستند. در مقابل، Interceptorها هم در کلاینت و هم در سرور قابل استفاده‌اند و دسترسی کاملی به پیام‌های Strongly-typed و متادیتاهای اختصاصی RPC دارند. لاگ‌گذاری جزئیات پیام، کشینگ خروجی متدها یا مدیریت خطا در ساختار RpcException با Interceptor اصولی‌تر انجام می‌شود.
۴مهم‌ترین اصل حفظ Backward Compatibility در فیلدهای Protobuf چیست و کلمهٔ کلیدی reserved چه نقشی دارد؟
در Protobuf شمارهٔ فیلد (Field Tag) شناسهٔ هویتی داده در حالت باینری است؛ بنابراین شماره یا نوع فیلدهای موجود هرگز نباید تغییر کند. اگر فیلدی حذف شود، شماره و نام آن باید با کلمهٔ کلیدی reserved مشخص شود تا توسعه‌دهندگان در آینده ناخواسته از همان شماره برای فیلد جدید استفاده نکنند و کلاینت‌های قدیمی دچار ناسازگاری و خواندن دادهٔ اشتباه نشوند.

سوالات تشریحی — ASP.NET Core و کلاینت

بخش دوم · ۵ و ۶ از ۱۰
۵برای تغییرات ناسازگار (Breaking Changes)، چه الگویی برای Versioning پکیج‌های Protobuf توصیه می‌شود؟
استاندارد صنعت، تفکیک بر مبنای فضای نام و پکیج (Package Versioning) است؛ مثلاً package order.v1; در نسخهٔ اول و package order.v2; در نسخهٔ جدید. با این رویکرد، Kestrel متدهای هر دو نسخه را هم‌زمان روی Routeهای مجزا سرویس‌دهی می‌کند. این کار امکان هم‌زیستی نسخه‌ها (Coexistence) و مهاجرت تدریجی کلاینت‌ها بدون Downtime را فراهم می‌کند.
۶هنگام اضافه کردن فیلد جدید به یک Contract در Protobuf، کلاینت‌های قدیمی و جدید چگونه با آن رفتار می‌کنند؟
اگر کلاینت با Contract قدیمی پیامی دریافت کند که فیلد جدیدی دارد، موتور Protobuf فیلد ناشناخته را نادیده می‌گیرد و آن را به‌عنوان Unknown Field نگه می‌دارد. همچنین اگر کلاینت جدید با Contract به‌روز پیامی بدون فیلد جدید دریافت کند، مقدار پیش‌فرض دیتاتایپ (مانند 0، "" یا false) به فیلد اختصاص می‌یابد؛ بنابراین سازگاری دوطرفه حفظ می‌شود.
